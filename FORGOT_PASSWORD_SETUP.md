# Forgot Password Setup Complete! 🎉

## ✅ What I've Implemented:

### 1. **API Functions** (apis.js)

- `forgotPassword(email)` - Sends reset email
- `resetPassword(email, token, newPassword)` - Resets password with token

### 2. **Login Component** (Login.jsx)

- Added "Forgot Password" clickable link
- Created Forgot Password modal that collects email
- Sends reset email when user submits

### 3. **Reset Password Page** (ResetPassword.jsx)

- New route: `/reset-password`
- Reads `token` and `email` from URL query parameters
- Validates password match and length
- Calls reset API and redirects to login on success

### 4. **Routing** (App.jsx)

- Added `/reset-password` route

## 🔧 Backend Update Required:

Your backend needs to update the reset link URL on **line 279** in your Account controller:

**Current code:**

```csharp
var resetLink = $"https://yourfrontend.com/reset-password?token={Uri.EscapeDataString(token)}&email={email}";
```

**Update to:**

```csharp
var resetLink = $"http://localhost:5175/reset-password?token={Uri.EscapeDataString(token)}&email={email}";
```

For production, use your actual frontend domain.

## 📧 How It Works:

### Step 1: User Clicks "Forgot Password"

- On login page, user clicks "Forgot Password" link
- Modal opens asking for email

### Step 2: Send Reset Email

- User enters email and clicks "Send Reset Link"
- Frontend calls: `POST /api/Account/forgot-password` with email
- Backend generates token and sends email with link like:
  ```
  http://localhost:5175/reset-password?token=ABC123&email=user@example.com
  ```

### Step 3: User Receives Email

- User clicks link in email
- Browser opens: `/reset-password?token=ABC123&email=user@example.com`

### Step 4: Reset Password

- ResetPassword page extracts `token` and `email` from URL
- User enters new password and confirms
- Frontend calls: `POST /api/Account/reset-password` with:
  ```json
  {
    "email": "user@example.com",
    "token": "ABC123",
    "newPassword": "newpass123"
  }
  ```

### Step 5: Success!

- Password is reset
- User redirected to login page
- Can now login with new password

## 🔒 Token Storage:

**You DON'T store the token!** The token is:

1. Generated by backend
2. Sent in email link
3. User clicks email → browser receives token in URL
4. Frontend reads token from URL and sends it back to backend
5. Backend validates token (checks expiry, user, etc.)

The token is single-use and expires in 1 hour (based on your backend code).
